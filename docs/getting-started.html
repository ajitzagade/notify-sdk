How to use notify-sdk

From a fresh clone to your first WhatsApp message, step by step.

This walks through everything in order: standing up the infrastructure, logging into the admin console, onboarding a client business as a "tenant," and sending its first message — both from the dashboard and programmatically.

About 15 minutes, first time through
Read this part first

There is no tenant login. Two different people use this platform, two different ways.

"Tenant" means a client business you're running WhatsApp for — not a user account. A tenant never signs into anything. Knowing which lane you're in decides everything that follows.

Your internal ops team

Logs into the admin console

Creates and configures tenants, enters WhatsApp credentials, sends test messages, watches analytics, issues API keys. This is the only place anyone actually signs in.

→ apps/admin, port 3012
A tenant's own backend

Calls the REST API with a key

The client business's developers — or their MCP-connected AI assistant — send messages and read logs using an API key ops issued them. No dashboard, no password, ever.

→ apps/api's /v1/*, port 3001
In short: steps 1–4 below are things you (ops) do once, in the admin console. Step 5 is what you hand off to a client's developers so their systems can integrate — that's the only "tenant-facing" part of this platform.
Before you start

Two separate checklists — one for your machine, one for the client's WhatsApp account.

Node.js + pnpm installed

This is a pnpm workspace monorepo — npm alone won't resolve the internal packages correctly.

Docker (or Colima on macOS) running

Postgres runs in a container on localhost:5434 — nothing else in this app needs a database elsewhere.

apps/admin/.env.local filled in

DATABASE_URL, NOTIFY_MASTER_KEY, SESSION_SECRET, BLOB_READ_WRITE_TOKEN, plus ADMIN_SEED_EMAIL/ADMIN_SEED_PASSWORD for your first login.

A verified Meta Business Manager + WABA

The client business must already own this — you'll need a System User access token, the WABA ID, an app secret, and a webhook verify token. This part isn't optional or fakeable in production.

Step 1 of 2 — one-time machine setup

Get the admin console running locally.

Run these once, in order, from the repo root. Later runs just need the last two.

1

Install dependencies

pnpm install
2

Start Postgres

Boots a container on port 5434. Data persists in a named volume between restarts.

docker compose up -d
3

Apply database migrations

Safe to re-run — every migration file is idempotent.

for f in packages/notify/src/adapters/storage/migrations/*.sql; do
  PGPASSWORD=notify psql -h localhost -p 5434 -U notify -d notify_sdk -f "$f"
done
4

Build the core SDK

The admin app and the API import compiled output from packages/notify — this step has to run at least once, and again after any SDK change.

pnpm --filter @orgname/notify build
5

Seed your first admin user

Reads ADMIN_SEED_EMAIL / ADMIN_SEED_PASSWORD from .env.local. There's no signup page by design — this script is the only way in the first time.

pnpm --filter admin seed:admin
6

Start the admin console and log in

Opens on localhost:3012. Sign in with the email/password from step 5.

pnpm --filter admin dev
You're in. Everything from here happens in the browser.

Enter WhatsApp credentials

Generate a key scoped to this tenant only. This is the credential their backend (or MCP-connected AI assistant) uses to send messages and read logs — they never get a login to this console.

What the client's backend actually does

One API call, authenticated with the key from step 5.

Requires apps/api running too — that's the process that actually serves /v1/*. Start it once with pnpm --filter @orgname/api-example dev (defaults to port 3001).

POSThttp://localhost:3001/v1/send
curl -X POST http://localhost:3001/v1/send \
  -H "Authorization: Bearer <the API key from step 5>" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "+15551234567",
    "template": "order_shipped",
    "data": { "orderId": "10482", "eta": "Friday" }
  }'

Swap template for hsmTemplate: { "name": "...", "language": "en_US" } to send a Meta-approved marketing template instead of a session message — the only way to reach someone outside the 24-hour customer-service window.

When something doesn't work

The four things that trip people up first.

The admin console won't log in / says credentials invalid
Re-run pnpm --filter admin seed:admin — it's idempotent and prints the account it finds or creates. Check ADMIN_SEED_EMAIL/ADMIN_SEED_PASSWORD in .env.local match what you're typing.
I edited something in apps/api and nothing changed
apps/api runs via ts-node with no file watcher. Kill and restart pnpm --filter @orgname/api-example dev after editing anything under src/lib/tenantRegistry.ts or its imports.
Credential save fails with a Meta API error
That's the platform working as intended — credentials are verified live against Meta's Graph API before they're allowed to persist. Double-check the token hasn't expired and has WhatsApp messaging permission.
A change to packages/notify isn't showing up
Re-run pnpm --filter @orgname/notify build — both apps/admin and apps/api's /v1 routes only pick up the compiled output, not the source directly.
notify-sdk — internal ops console (apps/admin) + tenant-facing /v1 REST API (apps/api). No tenant self-service login exists by design.
